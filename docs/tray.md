# 트레이 앱 — `cimon-tray`

빌드 머신에 로그인한 관리자가 작업 표시줄 알림 영역(「숨겨진 아이콘 표시」)에서 cimon 서비스의 상태를 보고, 켜고 끄고, 관리자 명령을 실행하게 하는 작은 Windows 앱이다. 지금은 이 일들이 매번 관리자 PowerShell 을 열고 `sc.exe`·`cimon.exe` 를 손으로 치는 일이다 — 특히 새 버전을 올리는 세 줄(중지·복사·시작).

상태: 설계. 구현 전.

## 1. 범위

| 한다 | 하지 않는다 |
|---|---|
| 서비스 상태·실행 중/대기 작업 수를 아이콘과 툴팁으로 | 작업 목록·로그 보기 — 웹 화면을 연다 |
| 서비스 시작 · 중지(지금 / 작업이 끝나면) · 재시작 | 빌드 요청 — Claude Code 의 일 |
| 관리자 명령(UAC 로 올린 창): 초대 코드, doctor, provision, 새 버전 올리기, 관리자 PowerShell | 관리자 권한을 늘 쥐고 있기 · 권한 있는 상주 도우미 |
| 상태가 바뀌면 알림(예기치 않은 중지, 작업 끝나고 중지됨) | 팀원 PC 에서 원격 서비스 제어 — 그 PC 들은 서비스가 없다 |
| 로그인할 때 자동 실행(사용자별 선택) | |

「관리자 실행」 은 위의 관리자 명령을 UAC 로 권한을 올려 실행하는 것으로 읽었다. 서비스 자체를 관리자 계정으로 돌리는 것이 아니다 — 서비스는 지금처럼 `NT SERVICE\cimon` 이다.

## 2. 구조

```
사용자 세션(관리자 계정이지만 UAC 로 걸러진 토큰)
  cimon-tray.exe ──── SCM: 상태 조회 · 시작 · 중지 · 사용자 정의 제어(작업 끝나면 중지)
       │                 └ 권한: 서비스 DACL 의 cimon-operators 그룹(§4.1), 없으면 UAC
       ├──────────── http://127.0.0.1:8770/healthz (사용자 토큰) — 대기·실행 수, draining, 경고
       └── ShellExecuteEx "runas" ──> cimon.exe <명령> --pause   (UAC, 자기 콘솔 창에서 실행·결과 표시)
                                        powershell (관리자, $c 준비)
NT SERVICE\cimon
  cimon.exe service  ← 사용자 정의 제어 128(작업 끝나면 중지) · 129(취소)
```

- **별도 실행 파일** `cimon-tray.exe`(GUI 서브시스템). `cimon.exe` 는 콘솔 프로그램이라 트레이로 띄우면 콘솔 창이 뜬다. `C:\Program Files\cimon\` 에 `cimon.exe` 와 나란히 둔다.
- **사용자 권한으로만 돈다.** 관리자 일은 그때마다 UAC 로 올린 별도 프로세스가 하고, 트레이는 그 결과를 기다리지 않는다(올린 창이 결과를 보여 준다). 그래서 트레이에는 권한을 노리는 공격면이 없다 — 명령을 받는 파이프·포트·상주 서비스를 만들지 않는다.
- 세션마다 하나(`Local\cimon-tray` 뮤텍스). 다른 사용자 세션의 트레이와는 무관하다.

## 3. 화면

### 3.1 아이콘과 툴팁

| 상태 | 아이콘 | 툴팁 |
|---|---|---|
| 실행 중, 작업 없음 | 초록 | `cimon — 실행 중` |
| 실행 중, 작업 있음 | 파랑 | `cimon — 작업 1 · 대기 2` |
| 작업 끝나면 중지 대기(드레인) | 노랑 | `cimon — 작업 1 끝나면 중지` |
| 시작 중 · 중지 중 | 노랑(반투명) | `cimon — 중지 중…` |
| 중지됨 | 회색 | `cimon — 중지됨` |
| 실행 중인데 `/healthz` 가 답하지 않음 | 빨강 | `cimon — 응답 없음(서비스는 실행 중)` |
| 서비스가 설치되지 않음 | 회색 + `!` | `cimon — 서비스 없음(cimon setup)` |

툴팁은 128자 안이다. 16·20·24·32 px 아이콘을 리소스에 넣어 DPI 에 맞게 고른다. 토큰이 없으면(§5.2) 작업 수 없이 서비스 상태만 보인다.

### 3.2 메뉴(오른쪽 클릭)

```
cimon — 실행 중 · 작업 1 · 대기 0        (회색, 상태 줄)
────────────────────────────
웹 화면 열기
────────────────────────────
시작                                    (중지됐을 때만)
중지 ▸   작업이 끝나면 중지               (작업이 있을 때 기본)
         지금 중지 — 실행 중인 작업은 중단된다
         작업 끝나면 중지 취소             (드레인 중일 때만)
재시작
────────────────────────────
관리자 ▸ 초대 코드 만들기…
         새 버전 올리기…
         툴체인 설치(provision)…
         점검(doctor)
         설정 파일 열기
         관리자 PowerShell 열기
────────────────────────────
로그인할 때 시작                          (체크)
알림 ▸   서비스가 멈추면 (체크, 기본 켬)
         작업이 끝나면 (체크, 기본 끔)
작업 표시줄에 항상 보이게…                (Windows 설정 열기)

```

왼쪽 클릭은 메뉴를 연다(왼쪽 더블클릭은 웹 화면).

- 관리자 항목 옆에는 방패 아이콘을 둔다 — 누르면 UAC 가 뜬다는 표시다.
- 시작·중지·재시작은 cimon-operators 권한이 있으면 방패 없이 바로 된다. 없으면 방패를 달고 UAC 로 간다.

### 3.3 알림

`Shell_NotifyIcon` 의 `NIF_INFO`(Windows 11 에서는 알림 센터 토스트)로 보낸다.

| 언제 | 내용 |
|---|---|
| 실행 중이던 서비스가 트레이가 시키지 않았는데 멈춤 | `cimon 이 멈췄다 — 서비스는 실패 시 다시 시작한다(10초 뒤)` |
| 멈췄다가 다시 실행 중 | `cimon 이 다시 실행 중` |
| 「작업 끝나면 중지」 가 끝남 | `cimon 을 멈췄다 — 작업 j000123 이 끝났다` |
| (선택) 작업이 끝남 | `j000123 example-app build 통과` — 기본 끔. 작업 결과는 Claude Code 가 이미 알린다 |

### 3.4 「숨겨진 아이콘 표시」

Windows 11 은 새 알림 아이콘을 숨겨진 아이콘 칸(^)에 넣는다. 작업 표시줄로 꺼내는 것은 사용자가 끌어다 놓거나 설정(개인 설정 > 작업 표시줄 > 기타 시스템 트레이 아이콘)에서 켜는 일이다. 앱이 스스로 꺼내는 공식 방법은 없고, 레지스트리를 고치는 우회는 쓰지 않는다.

- 아이콘은 **고정 GUID**(`NIF_GUID`)로 등록한다. 그래야 Windows 가 사용자가 고른 위치를 실행이 바뀌어도 기억한다. GUID 는 실행 파일 경로와 묶이므로 경로는 `C:\Program Files\cimon\cimon-tray.exe` 로 고정한다.
- 메뉴의 「작업 표시줄에 항상 보이게…」 는 `ms-settings:taskbar` 를 연다.

## 4. 서비스 제어와 권한

### 4.1 서비스 DACL — 누가 무엇을 할 수 있나

`sc.exe create` 가 준 지금의 DACL(실제 머신에서 `sc.exe sdshow cimon` 으로 확인):

```
D:(A;;CCLCSWRPWPDTLOCRRC;;;SY)(A;;CCDCLCSWRPWPDTLOCRSDRCWDWO;;;BA)(A;;CCLCSWLOCRRC;;;IU)(A;;CCLCSWLOCRRC;;;SU)
```

- **관리자(BA)도 UAC 로 걸러진 토큰에서는** 그 ACE 가 적용되지 않는다. 그래서 트레이(사용자 권한)는 시작·중지를 못 한다.
- **대화형 사용자(IU)에게는 `CR`(사용자 정의 제어)가 이미 있다.** 지금은 서비스가 사용자 정의 제어를 처리하지 않아 의미가 없다. 하지만 §4.2 의 제어 128 을 넣으면 **이 머신에 로그인한 누구나 서비스를 멈출 수 있게** 된다.

그래서 `cimon setup` 은 이제 DACL 을 **명시적으로 쓴다**(`sc.exe sdset`). 덧붙이지 않고 통째로 쓴다.

| 주체 | 권한 | 뜻 |
|---|---|---|
| SY(SYSTEM) | `CCLCSWRPWPDTLOCRRC` | 지금과 같다 |
| BA(관리자, UAC 로 올린 토큰) | `CCDCLCSWRPWPDTLOCRSDRCWDWO` | 지금과 같다 |
| IU · SU | `CCLCSWLORC` | 상태 조회만 — **`CR` 을 뺀다** |
| `cimon-operators` | `LCRPWPLOCRRC` | 상태 조회·시작·중지·사용자 정의 제어 |

**`cimon setup --operator <사용자>`(관리자, 한 번)** — 매번 UAC 를 띄우지 않고 켜고 끄려면 실행한다.

1. 로컬 그룹 `cimon-operators` 를 만들고 사용자를 넣는다. 걸러진 토큰에도 일반 그룹은 남으므로 UAC 없이 통한다.
2. 위 표대로 DACL 을 쓴다. `--operator` 없이 setup 을 다시 돌려도 그룹 ACE 는 유지한다 — 그룹이 있으면 넣는다.
3. 사용자가 다시 로그인해야 그룹이 토큰에 들어간다. setup 이 그렇게 안내한다.

`cimon-operators` 에 **주지 않는 권한**은 `DC`(설정 바꾸기)·`WD`·`WO`·`SD` 다. 설정을 바꿀 수 있으면 binPath 를 바꿔 서비스 계정 권한으로 아무 코드나 실행할 수 있기 때문이다.

- **남는 위험**: 그룹에 든 사람은 빌드를 멈출 수 있다(가용성). 권한을 넓히지는 못한다.
- **되돌리기**: `cimon setup --operator <사용자> --remove`. 그룹이 비면 ACE 도 지운다. `cimon doctor` 는 서비스 DACL 에 위험한 권한이 들어 있지 않은지 확인한다.

### 4.2 「작업이 끝나면 중지」 — 서비스가 스스로 멈춘다

지금 서비스를 멈추면 실행 중인 작업이 `interrupted` 로 끝난다(design §16.6). `cimon drain` 은 관리자로 돌며 `state\` 에 표시 파일을 쓰는데, 트레이는 거기에 쓸 수 없다. 그래서 **SCM 사용자 정의 제어**로 서비스에 맡긴다.

| 제어 코드 | 서비스가 하는 일 |
|---|---|
| 128 「작업 끝나면 중지」 | `draining` 을 켜서 새 작업을 거절하고, 실행 중인 작업이 0 이 되면 스스로 멈춘다(`SERVICE_STOPPED`, 종료 코드 0 — 실패가 아니라서 SCM 이 다시 시작하지 않는다). 대기 중인 작업은 그대로 둔다 — 다음에 시작하면 이어서 돈다 |
| 129 취소 | `draining` 을 끄고 계속 돈다 |

- 트레이는 `ControlService(128)` 만 보낸다. 상태는 `/healthz` 의 `draining` 과 SCM 상태로 본다.
- 128·129 를 처리하는 버전은 **§4.1 의 DACL 을 쓴 setup 과 함께** 나가야 한다. 그렇지 않으면 대화형 사용자 누구나 서비스를 멈출 수 있다. 서비스는 시작할 때 자기 DACL 을 읽어, IU·SU·WD 에 `CR`·`WP`·`DC` 가 있으면 128·129 를 받지 않고 서비스 로그와 `/healthz` 경고로 「`cimon setup` 을 다시 실행하라」 를 알린다.
- `cimon drain`(CLI)도 같은 제어를 보내도록 바꾼다 — 길이 하나가 된다. 서비스가 멈춰 있으면 지금처럼 표시 파일을 쓴다.
- **중지 메뉴의 기본값**: 실행 중인 작업이 있으면 「작업이 끝나면 중지」 다. 「지금 중지」 는 확인 창에서 실행 중인 작업 id 를 보여 준다.

### 4.3 권한이 없을 때

cimon-operators 가 아니면 시작·중지·재시작도 UAC 로 올린 `cimon.exe ctl <start|stop|drain-stop|cancel-drain|restart> --pause` 로 간다. 새 하위 명령 `cimon ctl` 은 SCM 을 직접 부르고 결과를 출력한다. 이름을 `service` 로 하지 않는 이유는, 그 이름이 이미 SCM 진입점(서비스 binPath 의 `cimon.exe service`)이기 때문이다 — 바꾸면 설치된 서비스의 binPath 가 깨진다.

## 5. 관리자 명령

### 5.1 실행 방식

모든 관리자 항목은 `ShellExecuteExW(lpVerb = "runas")` 로 **`cimon.exe` 를 직접** 올린다. 셸(`powershell -Command`·`cmd /c`)에 문자열을 이어 붙이지 않는다.

- **`--pause`(새 전역 플래그)**: 명령이 끝나면 `Enter 를 누르면 닫힌다` 를 보이고 기다린다. 올린 프로세스의 출력은 트레이로 가져올 수 없으니(UAC 경계), 그 콘솔 창이 결과(초대 코드, doctor 표)를 보여 준다. 종료 코드도 창에 적는다.
- **입력값**: 초대 이름·프로젝트 id 처럼 사용자가 넣는 값은 입력 창에서 `[A-Za-z0-9._-]{1,64}` 로 검사한 뒤에만 인자에 넣는다. 따옴표가 필요 없는 문자뿐이라 인자 경계가 깨지지 않는다. 경로(새 버전 파일)는 파일 선택 창에서 받고 MSVCRT 규칙으로 감싼다.
- 실행 파일 경로는 트레이 자신의 폴더의 `cimon.exe` 로 고정한다(PATH 를 찾지 않는다).

| 항목 | 올리는 명령 |
|---|---|
| 초대 코드 만들기… | 이름(과 「관리자로」 체크)을 묻고 `cimon.exe invite <이름> [--admin] --pause` |
| 점검(doctor) | `cimon.exe doctor --pause` |
| 툴체인 설치… | 프로젝트 id 를 묻고 `cimon.exe provision <project> --pause` |
| 새 버전 올리기… | 파일을 고르고 `cimon.exe upgrade --from <파일> --pause`(§5.3) |
| 설정 파일 열기 | `cimon.exe edit-config --pause` — 설정 파일을 찾아 메모장으로 열고, 닫으면 검사해 결과를 보인 뒤 「재시작할까?」 를 묻는다(설정은 시작할 때만 읽는다) |
| 관리자 PowerShell 열기 | `powershell.exe -NoExit -Command <고정 문자열>` — `$c` 와 `CIMON_CONFIG` 를 준비하고 루트 폴더로 간다. 사용자 입력이 들어가지 않는 유일한 셸 호출이다 |

트레이는 설정 파일 위치를 모르고 읽지도 못한다(`config\` 는 관리자만 읽는다). 그래서 위치를 찾는 일까지 올린 `edit-config` 가 한다. 저장 뒤 `Config::load` 로 검사하므로, 잘못 고친 설정이 다음 시작을 막는 일을 미리 잡는다.

### 5.2 상태를 읽는 토큰

`/healthz` 는 토큰이 있어야 작업 수를 준다. 트레이는 connect 스크립트가 만든 `%USERPROFILE%\.cimon\token.dpapi`(DPAPI, 이 Windows 사용자만 푼다)를 읽어 `Authorization` 헤더로 보낸다. 없으면 서비스 상태만 보이고, 메뉴에 「작업 수를 보려면 연결하기」(connect 한 줄을 안내)가 생긴다.

- 서버 주소는 `HKCU\Software\cimon\tray\Url`(기본 `http://127.0.0.1:8770`)이다.
- 토큰은 그 주소로만 보낸다. 주소는 `127.0.0.1`·`localhost` 의 http 이거나 https 여야 한다 — 설정이 틀려도 토큰이 다른 곳으로 새지 않게 한다.

### 5.3 `cimon upgrade` — 새 버전 올리기

오늘 손으로 한 세 줄(중지·복사·시작)과 그 앞뒤 확인을 한 명령으로 한다. 관리자로 돈다.

1. `--from` 파일의 sha256·크기·수정 시각과, 그 파일을 `--version` 으로 돌린 출력을 보이고 확인을 받는다. 확인을 건너뛰는 `--yes` 는 두지 않는다 — 관리자 권한으로 남이 바꿔 놓은 파일을 올리는 일을 사람이 한 번 본다.
2. 새 실행 파일로 `recipe check --main` 을 돌린다(design §16.6 의 1). 실패하면 멈춘다.
3. 드레인(제어 128)하고 서비스가 멈추기를 기다린다. 「지금」 을 고르면 바로 중지한다.
4. 지금 `cimon.exe` 를 `cimon.exe.prev` 로 옮기고 새 파일을 복사한다. 같은 폴더에 새 `cimon-tray.exe` 가 있으면 함께 바꾼다 — 실행 중인 트레이 파일은 이름을 바꿀 수 있으므로 `.prev` 로 옮기고 복사한다.
5. 서비스를 시작하고 `/healthz` 가 새 버전을 답할 때까지 기다린다(최대 60초). 답하지 않으면 `.prev` 로 되돌리고 다시 시작한다. 되돌렸다는 사실과 서비스 로그 위치를 출력한다.
6. 트레이는 자기 실행 파일이 바뀐 것을 보면(파일 해시를 1분마다 확인) 「새 버전이 설치됐다 — 트레이를 다시 시작」 알림을 띄우고, 누르면 스스로 다시 실행한다.

### 5.4 웹 화면 열기

리뷰 화면은 1회용 로그인 링크로 들어간다(지금은 MCP `web_login` 만 준다). 트레이를 위해 **`POST /ui/login-link`(사용자 토큰)** 를 더한다. `web_login` 과 같은 링크를 돌려주고, 트레이가 기본 브라우저로 연다. 웹 화면이 꺼져 있으면(`[web].enabled = false`) 메뉴 항목을 숨긴다.

## 6. 로그인할 때 시작과 설정

| 값 | 위치 | 기본 |
|---|---|---|
| 자동 실행 | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\cimon-tray` = 실행 파일 경로 | 처음 실행 때 묻는다 |
| 서버 주소 | `HKCU\Software\cimon\tray\Url` | `http://127.0.0.1:8770` |
| 알림 | `HKCU\Software\cimon\tray\Notify*` | 멈춤 켬, 작업 끝 끔 |

사용자별이다. 기계 전체 설치(`cimon setup`)는 실행 파일을 복사할 뿐 누구의 자동 실행도 켜지 않는다.

## 7. 구현

### 7.1 크레이트

```
crates/cimon-tray/      (새) 바이너리, #![windows_subsystem = "windows"]
  main.rs               뮤텍스, 숨은 창, 메시지 루프, TaskbarCreated 재등록
  icon.rs               Shell_NotifyIconW(NIF_GUID·NIF_TIP·NIF_INFO), 아이콘 리소스, 툴팁
  menu.rs               CreatePopupMenu·TrackPopupMenu, 방패 아이콘(SIID_SHIELD)
  status.rs             폴링 스레드: SCM(3초) + /healthz(10초) → PostMessage 로 UI 스레드에
  service.rs            OpenService·StartService·ControlService(STOP·128·129)
  elevate.rs            ShellExecuteExW "runas", 인자 감싸기·검사
  settings.rs           HKCU 설정, 자동 실행
  token.rs              token.dpapi 읽기(CryptUnprotectData)
  build.rs + tray.rc    아이콘·매니페스트(DPI 인식, 공통 컨트롤 v6)
```

- 의존성: 워크스페이스의 `windows-sys`(기능 `Win32_UI_WindowsAndMessaging`·`Win32_UI_Shell`·`Win32_System_Services`·`Win32_Graphics_Gdi` 추가), `reqwest`(`blocking`), `serde_json`. 트레이 UI 크레이트(`tray-icon`·`muda`)는 쓰지 않는다 — 메뉴 하나와 아이콘 하나라 Win32 직접 호출이 의존성보다 작다.
- 탐색기가 다시 시작하면 아이콘이 사라진다. `RegisterWindowMessageW("TaskbarCreated")` 를 받으면 다시 등록한다. 이 메시지를 받으려면 숨은 **일반** 창이 필요하다(메시지 전용 창은 브로드캐스트를 받지 못한다).

### 7.2 cimon 쪽 변경

| 어디 | 무엇 |
|---|---|
| `cimon/src/service.rs` | 사용자 정의 제어 128·129 처리. 「작업 끝나면 중지」 감시는 서빙 루프의 작업 하나가 맡는다 |
| `cimon/src/main.rs` | `ctl <start\|stop\|drain-stop\|cancel-drain\|restart\|status>` · `upgrade --from` · `edit-config` · 전역 `--pause` |
| `cimon/src/ops.rs` | setup 이 서비스 DACL 을 명시적으로 쓰고(§4.1) `cimon-tray.exe` 를 함께 복사 · `setup --operator <user> [--remove]` · `drain` 이 제어 128 을 보냄 · doctor 의 서비스 DACL 검사(IU·SU 에 `CR`, 누구에게든 `DC` 가 있으면 실패) |
| `cimon-web` | `POST /ui/login-link` |
| 문서 | setup.md(트레이 설치·`--operator`), design §4.2·§16.6, 이 문서 |

### 7.3 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| T1 | 상태만 보이는 트레이: 아이콘·툴팁·메뉴 상태 줄·웹 화면 열기·트레이 끝내기·탐색기 재시작 | 서비스를 손으로 켜고 끄면 3초 안에 아이콘이 바뀐다. 토큰이 있으면 작업 수가 보인다 |
| T2 | `cimon ctl` 하위 명령과 `--pause`, 트레이의 시작·지금 중지·재시작(UAC) | UAC 로 켜고 끈다. 거절하면 아무 일도 없다는 것이 메뉴에 보인다 |
| T3 | setup 의 명시적 DACL, `setup --operator`, 권한이 있으면 UAC 없이 | 걸러진 토큰에서 시작·중지가 된다. 설정 변경(`sc config`)은 거부된다. operators 가 아닌 대화형 사용자는 사용자 정의 제어를 보낼 수 없다 |
| T4 | 제어 128·129, 「작업이 끝나면 중지」, DACL 이 옛것이면 제어를 받지 않음 | 작업 중에 누르면 새 요청이 `draining` 으로 거절되고, 작업이 끝나면 서비스가 멈추고, SCM 이 다시 시작하지 않는다 |
| T5 | 관리자 명령: 초대·doctor·provision·설정 열기·관리자 PowerShell | 각 항목이 UAC 창에서 돌고 결과를 보인다. 이상한 이름은 입력 창에서 거절된다 |
| T6 | `cimon upgrade`, 트레이 자기 갱신 | 정상 파일은 교체되고 healthz 가 새 버전을 답한다. 일부러 깨진 파일은 되돌려지고 서비스가 다시 돈다 |
| T7 | 알림, 로그인할 때 시작, 설정 | 서비스를 강제로 죽이면 알림이 오고, 로그아웃·로그인 뒤 트레이가 뜬다 |

### 7.4 시험

- **단위**: 인자 검사·감싸기(이름 규칙, 공백·따옴표가 든 경로), 상태 기계(SCM 상태 × healthz 결과 → 아이콘), DACL 문자열 합치기(기존 SDDL 에 ACE 를 넣고, 위험한 권한이 없는지).
- **통합(시험 서비스)**: 시험용 이름의 서비스(`cimon-test`)를 만들고 다음을 확인한다.
  - 제어 128 → 작업이 끝난 뒤 멈춤
  - 129 → 계속 돎
  - operators ACE 가 있으면 시작·중지 되고 `ChangeServiceConfig` 는 거부됨
  - `upgrade` 되돌리기
  - 관리자 권한이 필요하므로 CI 대신 빌드 머신에서 `--ignored` 시험으로 돌린다.
- **수동**(실제 머신): UAC 창 내용, 숨겨진 아이콘 칸에서 꺼낸 위치가 재시작 뒤에도 유지, 탐색기 재시작, 고DPI·다크 모드 메뉴, 빠른 사용자 전환.

## 8. 보안 정리

| 위험 | 대응 |
|---|---|
| 트레이를 통해 권한을 얻는다 | 트레이는 사용자 권한뿐이고 명령을 받는 통로가 없다. 관리자 일은 매번 UAC(사용자가 보고 승인), 실행 파일은 고정 경로, 셸 문자열 조립 없음, 입력값은 문자 집합으로 제한 |
| operators 그룹으로 서비스를 바꾼다 | 시작·중지·조회·사용자 정의 제어만. 설정 변경·DACL 변경 권한은 주지 않고 doctor 가 확인한다 |
| 로그인한 아무나 「작업 끝나면 중지」 를 보낸다 | 기본 DACL 은 대화형 사용자에게 사용자 정의 제어를 준다 — setup 이 그것을 빼고 DACL 을 명시적으로 쓴다. 옛 DACL 이면 서비스가 제어를 받지 않는다 |
| 바뀐 실행 파일을 관리자로 올린다 | `upgrade` 가 sha256·버전을 보이고 확인을 받는다. 사용자 폴더(빌드 출력)의 파일을 올리는 것 자체는 지금 손으로 하는 배포와 같은 위험이다 |
| 토큰이 샌다 | DPAPI(사용자) 그대로, `127.0.0.1` 또는 https 주소로만 보낸다 |
| 「지금 중지」 로 남의 작업이 끊긴다 | 기본은 「작업이 끝나면 중지」, 「지금」 은 실행 중인 작업 id 를 보인 확인 뒤에만 |

## 9. 정할 것

1. **UAC 없이 켜고 끄기(cimon-operators)를 쓸지** — 권장한다. 쓰지 않으면 켜고 끌 때마다 UAC 가 뜬다.
2. **관리자 메뉴에 넣을 명령** — 위 여섯 가지(초대·새 버전·provision·doctor·설정·PowerShell)로 시작하고, 자주 쓰는 것이 생기면 더한다.
3. **팀원 PC 용 트레이**(서비스 제어 없이 내 작업 상태·알림만) — 이번 범위 밖. 원하면 같은 앱의 「원격 모드」 로 따로 설계한다.
